# Нефункциональные требования

## NFR-001 — Время ответа API
**Категория:** Производительность
**Источник:** -
**Описание:** Система должна обрабатывать не менее 95% API-запросов за время, не превышающее `TBD` секунд, при штатной нагрузке.

## NFR-002 — Время расчёта условий сплитования
**Категория:** Производительность
**Источник:** -
**Описание:** Система должна выполнять расчёт условий сплитования и формирование графика платежей не более чем за `TBD` секунды с момента получения необходимых данных о заказе.

## NFR-003 — Производительность при штатной нагрузке
**Категория:** Производительность
**Источник:** -
**Описание:** Система должна обеспечивать выполнение функциональных операций при штатной нагрузке, составляющей `TBD` запросов в секунду, без превышения установленных требований к времени ответа.

## NFR-004 — Формирование сплит-договора
**Категория:** Производительность
**Источник:** -
**Описание:** Система должна формировать сплит-договор не более чем за `TBD` секунд при нормальных условиях.

## NFR-005 — Доступность сервиса
**Категория:** Доступность
**Источник:** -
**Описание:** Система должна обеспечивать доступность API не менее **99,9% времени в течение календарного месяца**, за исключением согласованных периодов технических работ.

## NFR-006— Отказоустойчивость экземпляра сервиса
**Категория:** Доступность
**Источник:** -
**Описание:** Отказ одного экземпляра сервиса не должен приводить к недоступности API для пользователей при наличии других работоспособных экземпляров.

## NFR-007 — Защита от повторного списания
**Категория:** Надёжность
**Источник:** -
**Описание:** Повторная обработка одного и того же запроса на списание не должна приводить к повторному списанию денежных средств с Покупателя.

## NFR-008 — Согласованность состояния договора
**Категория:** Надёжность
**Источник:** -
**Описание:** Система не должна переводить сплит-договор в состояние, соответствующее успешно выполненной операции, если результат операции не был подтверждён Платежным шлюзом.

## NFR-009 — Хранение платёжных данных
**Категория:** Безопасность
**Источник:** -
**Описание:** Система не должна хранить полные данные банковской карты Покупателя. Для последующих операций система должна использовать идентификатор или токен платёжного инструмента, предоставленный Платежным шлюзом.

## NFR-010 — Защита передаваемых данных
**Категория:** Безопасность
**Источник:** -
**Описание:** Передача данных между Системой и внешними компонентами должна осуществляться с использованием защищённого соединения.

## NFR-011 — Аудит изменения статуса договора
**Категория:** Логирование и аудит
**Источник:** -
**Описание:** Система должна регистрировать каждое изменение статуса сплит-договора с указанием времени изменения и причины перехода.

## NFR-012 — Логирование платёжных операций
**Категория:** Логирование и аудит
**Источник:** -
**Описание:** Система должна регистрировать результаты взаимодействия с Платежным шлюзом для всех платёжных операций.
## NFR-013 — Масштабирование системы
**Категория:** Масштабируемость
**Источник:** -
**Описание:** Система должна поддерживать увеличение вычислительных ресурсов для обработки растущего количества запросов без изменения бизнес-логики приложения.

## NFR-014 — Сохранение работоспособности при росте нагрузки
**Категория:** Масштабируемость
**Источник:** -
**Описание:** Увеличение нагрузки до значения `TBD` запросов в секунду не должно приводить к потере или некорректной обработке платёжных операций.
